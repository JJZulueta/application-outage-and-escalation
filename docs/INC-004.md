# INC-004: Training Staff Portal unavailable

**Record:** Retrospective simulated service desk ticket  
**Analyst:** Justice Zulueta  
**Date:** 23 October 2026  
**Category:** Application availability  
**Status:** Resolved in lab

## Problem and scope

After a deliberate Ctrl+C stop of the local Python web server, Edge showed ERR_CONNECTION_REFUSED for http://staffportal.test:8000. One Windows 11 Pro VM was tested. Wider user impact and a production priority were not established.

## Investigation

1. Established a working server and browser baseline.
2. Stopped the server and reproduced the browser failure.
3. Confirmed the hostname resolved to 127.0.0.1.
4. Confirmed a direct HTTP request to 127.0.0.1:8000 failed.
5. Queried listening connections on port 8000; no output was returned with errors suppressed. Combined with the deliberate stop and failed connection, this supported the stopped-server assessment.
6. Prepared escalation notes and a draft user update in Notepad.

## Simulated handover

Requested application server restoration, followed by service desk verification. No real receiving team, approval, or communication was involved. The same lab operator performed the recovery action.

## Recovery and verification

Started the same Python foreground server again. A second PowerShell window showed a listening TCP endpoint at 127.0.0.1:8000 and HTTP 200 OK through the portal hostname. Refreshing Edge displayed the expected portal page. Appended resolution notes and a draft recovery message.

## Cause and closure

Cause was the deliberate server stop in this controlled exercise. The incident is resolved based on the operator's local tests. No independent user confirmation, SLA timing, sustained monitoring, or production root-cause investigation is claimed.

Follow the support runbook and permissions for recovery. Escalate recurring failures, failed startup, wider impact, or failures after apparent recovery. Maintain ownership of user updates and verify the affected workflow before closure.
